This guide takes you from an empty directory to a running Day app. You will install the CLI,
choose one platform, and edit the app’s first screen. You need a terminal and a text editor;
the examples assume you can read basic Rust.

## 1. Install the CLI

Install [Rust through rustup](https://rustup.rs) and [Git](https://git-scm.com/downloads), then install Day’s command-line tool:

<InstallCommand />

Check the installation and available toolchains:

```bash
day --version
day doctor
```

`day doctor` reports missing tools. You only need to install the tools for your chosen target; the Rust standard library a cross-compiled target needs is added by the first build.
See [system requirements](/docs/system-requirements) for supported versions and installation details.

## 2. Choose a platform and run your app

Select your development computer and the platform you want to run on. Install the listed
requirements, then run the commands in a terminal. The first build downloads and compiles
dependencies, so allow more time than for later builds.

<PlatformSetup />

The selector covers the main targets. GTK and Qt also run on macOS and Windows for development;
see [all platform combinations](/docs/platforms) for those options.

The generated project contains a `Day.toml` app manifest, Cargo dependencies pinned to a Day
release, and platform files for your chosen toolkit. Open `src/lib.rs` to find `root()`, the
function that defines your app’s interface. [Project structure](/docs/project-structure)
explains the other files.

If the app does not launch, use the [troubleshooting guide](/docs/troubleshooting), run `day doctor` again and check the target’s setup instructions
above. Mobile targets need a running emulator, simulator, or connected device as described there.

## 3. Make your first change

First add these messages to `resource/locales/en-US/app.ftl` (or the scaffold's default
locale). Keep the existing `app_title` and other messages:

```ftl
hello_from_my_first_edit = Hello from my first edit
tap_me = Tap me
add_one = Add one
counter_value = Count: { $count }
```

> [!TIP]
> **Put interface text in the catalog.** Raw string literals are accepted, but use generated
> `res::str` accessors for human-readable text, including hints and errors. They check message
> names and arguments at compile time and follow the selected language. See
> [Localization](/docs/localization) for the catalog and code generation setup.

Open `src/lib.rs`. Keep its `use day::prelude::*;` and `day::resources!()` declarations.
The scaffold's `root()` returns the whole UI; replace it with:

```rust
pub fn root() -> impl Piece {
    column((
        label(res::str::hello_from_my_first_edit()),
        button(res::str::tap_me())
            .action(|| println!("tapped"))
            .id(id!(greeting_button)),
    ))
    .spacing(Space::M)
    .padding(Space::L)
}
```

Run the `day launch` command for your selected target again to see the change.
[Pieces](/docs/pieces) explains how `column`, `label`, and `button` compose the interface.

## 4. Make the screen respond

Replace `root()` again to give the button something visible to do:

```rust
pub fn root() -> impl Piece {
    let count = Signal::new(0i64);

    column((
        label(res::str::counter_value(count)).id(id!(counter_label)),
        button(res::str::add_one())
            .action(move || count.update(|n| *n += 1))
            .id(id!(increment_button)),
    ))
    .spacing(Space::M)
    .padding(Space::L)
}
```

Rebuild and launch. Pressing **Add one** should change the count on screen. The `Signal`
holds the value; passing it to `counter_value` keeps the message reactive to both the count
and the selected language. Passing `count.get()` instead would capture only the initial count.

The `id!(counter_label)` and `id!(increment_button)` declarations give tests stable targets.
These identifiers do not change when the visible text is translated. The
[dayscript guide](/docs/dayscript) tests this screen using those IDs and the message key.

## Optional: add another target

Once the app works on your first platform, install another target’s tools and add it to the project:

```bash
day project add-target web-dom
day launch -t web-dom
```

This example adds the experimental web target. Use a different target name if you prefer.
Your UI code is shared, but platform capabilities differ; test the features your app uses on
each target you plan to ship.

## Optional: editor integration

The [Day VS Code extension](https://github.com/daybrite/day-vscode)
adds project creation, build and run controls, and diagnostics to the editor.
You can also use [AI-assisted development](/docs/ai) to edit and test your app. Neither is
required to follow this guide.

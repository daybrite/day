`linux-gtk` is a Tier 2 desktop target using GTK 4 and libadwaita. It provides a GTK interface
for the app code you share with other systems. Install the development libraries required by
your distribution and check the toolkit’s accessibility limitations before choosing it.

## Getting started

GTK 4.10+, libadwaita 1.5+, and librsvg 2.52+ development files are required
(Ubuntu 24.04 and Fedora 40 satisfy these):

```sh
sudo apt install libgtk-4-dev libadwaita-1-dev librsvg2-dev pkg-config   # Debian/Ubuntu
sudo dnf install gtk4-devel libadwaita-devel librsvg2-devel pkgconf     # Fedora

cargo install --git https://github.com/daybrite/day day-cli
day new app my-app --toolkit linux-gtk
cd my-app
day launch -t linux-gtk
```

Add `libwebkitgtk-6.0-dev` if you use the web view piece. Sound effects play through [libpulse](https://www.freedesktop.org/software/pulseaudio/doxygen/),
which a desktop already has ([system requirements](/docs/reference/system-requirements#optional-sound-effects)). `day doctor --toolkit gtk` probes
GTK 4, libadwaita, librsvg, `glib-compile-resources`, and the packaging tools (`flatpak-builder`,
`linuxdeploy`, `linuxdeploy-plugin-gtk`); it does not check WebKitGTK.

```sh
day pack -t linux-gtk        # single-file .flatpak AND a portable .appimage
```

`day pack` produces both formats by default. The flatpak runtime supplies GTK itself
(`org.gnome.Platform`), so that bundle carries only your app and its assets; A user installs it with
`flatpak install ./my-app-1.0-linux-gtk-x86_64.flatpak`. The AppImage carries its own GTK, so a user
marks it executable and runs it.

## Caveats

- libadwaita is required. The window, navigation, tabs, dialogs and animations are all
  Adwaita types; a plain-GTK build is not a supported configuration.
- [`GtkVideo`](https://docs.gtk.org/gtk4/class.Video.html) needs a GStreamer media toolkit in the GTK build. Distro packages ship one;
  Homebrew's gtk4 does not, so the media piece shows GTK's own "no media toolkit" error on
  `macos-gtk`.
- Lottie and map have no GTK arm; each renders its placeholder. [`cover()`](https://daybrite.dev/api/day_pieces/fn.cover.html) presents as
  a topmost window-sized child (no transition, programmatic dismissal only).
- The combo box uses [`GtkComboBoxText`](https://docs.gtk.org/gtk4/class.ComboBoxText.html), deprecated in GTK 4.10 but kept because GTK has no
  editable replacement yet.
- A [`progress`](https://daybrite.dev/api/day_pieces/fn.progress.html) node picks its widget at realize time: [`progress(f)`](https://daybrite.dev/api/day_pieces/fn.progress.html) becomes a [`GtkProgressBar`](https://docs.gtk.org/gtk4/class.ProgressBar.html)
  and [`spinner()`](https://daybrite.dev/api/day_pieces/fn.spinner.html) a [`GtkSpinner`](https://docs.gtk.org/gtk4/class.Spinner.html). A node that starts indeterminate will not turn into a bar on a
  later value change; use separate nodes if you need both.
- Canvas text uses cairo's toy text API, not Pango, so complex-script shaping inside a
  [`canvas`](https://daybrite.dev/api/day_pieces/fn.canvas.html) is weaker than in a [`label`](https://daybrite.dev/api/day_pieces/fn.label.html).
- GTK on macOS and Windows (`macos-gtk`, `windows-gtk`) exists for development convenience only
  ([Tier 4](/docs/reference/platforms#support-tiers)); `day pack` skips them, and the accessibility tree is
  absent (GTK's a11y bridge is Linux-only). `windows-gtk` builds
  against MSYS2's GTK 4 with a GNU Rust toolchain
  ([setup](/docs/reference/platforms/windows-winui#qt-and-gtk-on-a-windows-host)); there is no WebKitGTK 6 for
  Windows, so the web view is a placeholder there, and bundled custom fonts don't register with
  Pango.

`windows-winui` hosts Windows' own XAML controls in a plain Win32 window through
[XAML Islands](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/xaml-islands).
There is no framework runtime for your users to install.

<PlatformShots platform="windows-winui" shots={["home", "controls", "dates", "grid"]} />

> **Which XAML, precisely.** This backend uses **system XAML** — the `Windows.UI.Xaml` stack that
> ships inside Windows 10 and 11 — not WinUI 3 / the Windows App SDK. The distinction is not
> cosmetic: many control names exist in both namespaces with different behaviour (this
> `ProgressRing` is the UWP dotted ring, not WinUI 3's arc; `Pivot` doesn't exist in WinUI 3 at
> all). **The links in the table below therefore point at the UWP `Windows.UI.Xaml` API
> reference**, which is the documentation that actually applies here — not the WinUI 3 control
> pages, which describe different types. The target keeps the name `windows-winui` for continuity.

## Getting started

You need the Visual Studio C++ Build Tools (for MSVC and the Windows SDK) and the MSVC Rust
toolchain. The C++/WinRT shim is compiled by `build.rs` against the plain Windows SDK.

```powershell
rustup default stable-msvc
cargo install day-cli
day new app my-app --toolkit windows-winui
cd my-app
day launch -p windows-winui
```

`day doctor --toolkit winui` checks the SDK and toolchain.

```powershell
day pack -p windows-winui     # .msix plus an NSIS -setup.exe
```

The NSIS installer is per-user: no elevation, a normal Add/Remove Programs entry, and a silent
`/S` mode for managed deployment.

## Caveats and special considerations

- **Less real-application mileage** than the Apple, Linux and Android targets. It builds and runs
  the full UI walkthrough in CI on every push, but calibrate expectations accordingly.
- **The web view needs the WebView2 Runtime.** Day hosts a
  [WebView2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) composition visual —
  not the legacy EdgeHTML `WebView`. The runtime ships with Windows 11 and current Windows 10; if
  it is absent, the piece shows its URL-label fallback instead of failing.
- **No native segmented control exists in system XAML**, so `picker().segmented()` is a horizontal
  row of radio buttons.
- **The inline time picker falls back to a flyout** — system XAML has no inline clock.
- **Text-area read-only, selectable and spell-check patches are accepted but do nothing**; those
  capabilities report unsupported.
- **No `cover()`, no Lottie, no map** on this backend — each renders its placeholder.
- **Radial gradients in a `canvas` are synthesized** into a bitmap brush, because system XAML has
  `LinearGradientBrush` but no `RadialGradientBrush` (that type is WinUI-only).

## What each piece becomes

| Day piece | XAML control (`Windows.UI.Xaml.Controls`) |
|---|---|
| `column` / `row` / `stack` / `section` | [`Canvas`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.canvas) (Day positions children absolutely) |
| `label` | [`TextBlock`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.textblock) |
| `button` | [`Button`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.button) (`AccentButtonStyle` when prominent) |
| `toggle` | [`ToggleSwitch`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.toggleswitch) |
| `slider` | [`Slider`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.slider) |
| `text_field` | [`TextBox`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.textbox) |
| `text_area` | [`TextBox`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.textbox) with `AcceptsReturn` |
| `picker().menu()` | [`ComboBox`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.combobox) |
| `picker().segmented()` / `.inline()` | [`RadioButton`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.radiobutton)s in a horizontal / vertical stack |
| `progress(f)` | [`ProgressBar`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.progressbar) |
| `spinner()` | [`ProgressRing`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.progressring) |
| `divider` | [`Border`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.border), 1px, themed stroke |
| `scroll` | [`ScrollViewer`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.scrollviewer) |
| `list` | [`ScrollViewer`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.scrollviewer) with Day-side cell pooling |
| `nav` (split and stack) | [`NavigationView`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.navigationview) |
| `nav_menu` | `NavigationViewItem`s, or a [`ListView`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.listview) standalone |
| `tabs` | [`Pivot`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.pivot) |
| `image` | [`Image`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.image) |
| `canvas` | [`Canvas`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.canvas) with a `Path` per shape |
| dialogs / alerts / prompts | [`ContentDialog`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.contentdialog) |
| file dialogs | [`FileOpenPicker`](https://learn.microsoft.com/en-us/uwp/api/windows.storage.pickers.fileopenpicker) / `FileSavePicker` |
| menu bar | [`MenuBar`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.menubar) |
| context menus | [`MenuFlyout`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.menuflyout) |
| *external* `activity()` | [`ProgressRing`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.progressring) |
| *external* `combobox()` | editable [`ComboBox`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.combobox) |
| *external* `search_field()` | [`AutoSuggestBox`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.autosuggestbox) |
| *external* `date_picker()` | [`CalendarDatePicker`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.calendardatepicker), or [`CalendarView`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.calendarview) inline |
| *external* `time_picker()` | [`TimePicker`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.timepicker) |
| *external* `media()` | [`MediaPlayerElement`](https://learn.microsoft.com/en-us/uwp/api/windows.ui.xaml.controls.mediaplayerelement) |
| *external* `webview()` | WebView2 composition visual inside a `Border` |

**Text measurement** is XAML's own measure pass (`Measure` → `DesiredSize`), with a re-measure
after forcing layout when a templated control reports zero before the island's first async pass.

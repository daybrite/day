`harmony-arkui` drives ArkUI through its **NDK C node API** — `ARKUI_NODE_BUTTON` and friends —
from a Rust `cdylib`, inside an ArkTS host project that hvigor packages into a `.hap`. It is
Day's newest backend — [Tier 3 · Experimental](/docs/platforms#support-tiers) — and this page
says exactly where that shows.

## Getting started

This is the least ergonomic toolchain Day supports. You need the OpenHarmony SDK plus the
command-line tools (hvigor, `hdc`, the signing tools); `day doctor --toolkit harmonyos` checks
each piece and prints setup help, and the [HarmonyOS notes](/docs/internal/harmonyos) cover the
install in detail.

```sh
cargo install day-cli
day new app my-app --toolkit harmony-arkui
cd my-app
day build -p harmony-arkui       # cross-compiles, then hvigor → signed .hap
day launch -p harmony-arkui      # installs and starts on an emulator or device
```

`day build` signs the `.hap` with the public development certificate, so you get an installable
artifact without a vendor account. `day pack -p harmony-arkui` produces the release `.hap`, signed
with your own material when configured.

The [`day ohos`](/docs/cli) subcommand wraps the emulator: `day ohos emulator launch` (add
`--headless` for CI) boots the Oniro QEMU image and connects `hdc` without leaving the CLI. It
does not download images: point `DAY_OHOS_EMULATOR` at a directory holding the Oniro emulator
images (default `~/ohos/emulator/images`), or the command errors naming what is missing.

## Caveats and special considerations

This backend implements the widget vocabulary well and the surrounding platform integration
partially. Concretely:

- **No dialogs.** `present()` handles file open/save; alerts and prompts are ignored. If your UI
  depends on a confirmation dialog, it will silently do nothing here.
- **Several external pieces have no ArkUI arm** — media, map, Lottie, search field, combo box,
  activity indicator, and remote image all render a placeholder. The date/time pickers and
  pull-to-refresh have native arms, and the web view has an **ArkTS** arm: the crate ships its own
  ArkTS component, staged into the host project via `[package.metadata.day.ohos]`, with load,
  back/forward, stop, and reload working.
- **All three picker styles collapse to one control** — menu, segmented and inline all become
  `ARKUI_NODE_TEXT_PICKER`.
- **Layout is measured for very few kinds.** Labels, buttons and the text area ask ArkUI to
  measure; nearly everything else uses a fixed size, so unusual content may not fit as snugly as
  it does on other targets.
- **Much of the platform requires ArkTS**, reached through the host project rather than the C API:
  navigation (`Navigation`/`NavPathStack`), file pickers, opening a URL, bundled resources, custom
  font registration, and app bootstrap. Day wires all of this for you in the scaffold — it is worth
  knowing when you go past what Day models.
- **Emulator behavior in CI is tolerated-flaky**; the build and packaging steps gate hard.

## What each piece becomes

The generated, CI-checked [coverage matrix](/docs/internal/coverage-matrix) is the always-current version of this data across every backend; the table here adds the per-class links and notes.

Day calls the ArkUI native node API directly, so the mapping below is in terms of `ArkUI_NodeType`
values. Where HarmonyOS's [NDK development guides](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/arkts-use-ndk)
cover a component, the node type links to that guide; the rest link to the OpenHarmony
`ArkUI_NodeType` reference.

| Day piece | ArkUI node type |
|---|---|
| `column` / `row` / `stack` / `section` | [`ARKUI_NODE_STACK`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-layout-container) |
| `label` | [`ARKUI_NODE_TEXT`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-use-text-component) |
| `button` | [`ARKUI_NODE_BUTTON`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-build-form-components#button-component) |
| `toggle` | [`ARKUI_NODE_TOGGLE`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-build-form-components#toggle-component) |
| `slider` | [`ARKUI_NODE_SLIDER`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-build-form-components#slider-component) |
| `text_field` | [`ARKUI_NODE_TEXT_INPUT`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-textarea-event) |
| `text_area` | [`ARKUI_NODE_TEXT_AREA`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-textarea-event) |
| `picker()` (all three styles) | [`ARKUI_NODE_TEXT_PICKER`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) |
| `progress(f)` | [`ARKUI_NODE_PROGRESS`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) |
| `spinner()` | [`ARKUI_NODE_LOADING_PROGRESS`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) |
| `divider` | a 1 vp tinted `ARKUI_NODE_STACK` (no divider node type) |
| `scroll` | [`ARKUI_NODE_SCROLL`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) |
| `list` | [`ARKUI_NODE_LIST`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-loading-long-list) with a [node adapter](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-loading-long-list#implementing-lazy-loading) (real recycling) |
| `tabs` | [`ARKUI_NODE_SWIPER`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-swiper) |
| `nav` | `ARKUI_NODE_STACK`, with pushed pages re-homed into ArkTS `NavDestination`s |
| `nav_menu` | a scroll + column of row nodes |
| `cover()` | `ARKUI_NODE_STACK` re-homed onto the window root |
| `image` | [`ARKUI_NODE_IMAGE`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) |
| `vector` | [`ARKUI_NODE_IMAGE`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) rendering the staged SVG from `rawfile day/` natively |
| `canvas` | [`ARKUI_NODE_CUSTOM`](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ndk-build-custom-components#custom-drawing-component) drawn with OH_Drawing |
| *external* `date_picker()` | [`ARKUI_NODE_DATE_PICKER`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) inline, [`ARKUI_NODE_CALENDAR_PICKER`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) compact |
| *external* `time_picker()` | [`ARKUI_NODE_TIME_PICKER`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) |
| *external* `pull_refresh()` | [`ARKUI_NODE_REFRESH`](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkui/capi-native-node-h.md#arkui_nodetype) |
| *external* `webview()` | the ArkTS `Web` component — the piece's own ArkTS, staged via `[package.metadata.day.ohos]` (the C node API has no Web node) |

> [!WARNING] Deprecated
> `windows-xaml` is [Tier 5 · Deprecated](/docs/reference/platforms#support-tiers): superseded by
> [`windows-winui`](/docs/reference/platforms/windows-winui), the Windows target new apps get. It remains in the target registry for
> existing projects; current build, packaging, and runtime success are not established here. The
> CLI prints `warning: windows-xaml is deprecated; move to windows-winui`.

## Moving to `windows-winui`

```powershell
day project add-target windows-winui
```

Then drop `windows-xaml` from `Day.toml`. The Rust code needs no changes: both targets build the
same Rust toolkit implementation and the same C++/WinRT shim. Development machines need the Windows App Runtime
2.5.1 or newer; a packed `windows-winui` app is self-contained, so its users install nothing extra.
The [Windows (WinUI 3)](/docs/reference/platforms/windows-winui) page covers setup, packing, caveats, and
which control each Day piece becomes.

## What differs

- **The XAML stack.** `windows-xaml` builds the toolkit against **system XAML**
  (`Windows.UI.Xaml`, part of Windows 10 and 11), hosted in the Win32 window through [XAML
  Islands](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/xaml-islands).
  `windows-winui` builds it against WinUI 3 (`Microsoft.UI.Xaml`) from the Windows App SDK, hosted
  through that SDK's `DesktopWindowXamlSource`.
- **No Windows App SDK runtime.** System XAML ships with Windows, so a `windows-xaml` build
  neither downloads the SDK packages nor needs the Windows App Runtime.
- **The controls** are system XAML's (UWP) versions, not WinUI 3's, and the web view is a WebView2
  composition visual the shim hosts by hand rather than WinUI's `WebView2` control.

Building and packing are otherwise the same: the MSVC toolchain and the Visual Studio C++ Build
Tools, `day doctor --toolkit xaml`, and `day pack -t windows-xaml` for an `.msix` plus an NSIS
`-setup.exe`. dayscript gates naming `xaml` or `windows-xaml` also match `windows-winui`.
